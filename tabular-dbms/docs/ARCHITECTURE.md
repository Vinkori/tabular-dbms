# Архітектура

Браузерний і десктопний клієнти передають JSON-запити FastAPI.
Маршрути перевіряють форму через Pydantic і викликають сервіси.
Домен відповідає за правила даних; репозиторій — за збереження.

| Рівень | Компоненти | Відповідальність |
|---|---|---|
| Інтерфейси | backend/web, desktop | Введення, відображення, запити, повідомлення |
| HTTP | api.py, schemas.py, main.py | Контракт, форма запитів, статуси |
| Сервіси | DatabaseService, TableService | Координація та блокування |
| Домен | Database, Table, Column, Row, DataType | Схема, значення, дублікати |
| Збереження | JsonDatabaseRepository | JSON, відновлення, імпорт/експорт |

## Цикл зміни

1. API перевіряє форму запиту.
2. Сервіс захоплює спільний threading.Lock.
3. Репозиторій завантажує storage/<UUID>.json.
4. Домен перевіряє дані та виконує операцію.
5. Репозиторій записує тимчасовий файл і замінює цільовий через os.replace.
6. API повертає результат або спільну форму помилки.

Lock охоплює load/change/save в одному процесі. Це не міжпроцесна або
розподілена транзакція. Клієнти не редагують серверне сховище напряму.

## Типи та дублікати

normalize перевіряє й перетворює значення, canonicalize створює хешований
ключ, to_json/from_json визначають представлення у файловому форматі.
Row.canonical_key проходить усі колонки в порядку схеми без UUID рядка.
Для кольору ключ — RGB-кортеж, для інтервалу — пара RGB-кортежів.
Table.remove_duplicates використовує множину ключів і зберігає перші рядки.
Очікуваний час O(n × m) для n рядків і m колонок за звичайних припущень
щодо хешування й розміру значень.

## Клієнти та помилки

API повертає JSON із кодом, повідомленням і, за можливості, назвою поля.
Desktop використовує QThreadPool для мережевих задач. Якщо результат зміни
після мережевої помилки невідомий, пропонується оновити дані перед повтором.
Web отримує статичні файли від того самого сервера та використовує Fetch API.
Оновлення між клієнтами — за запитом користувача, без push-підписок.
